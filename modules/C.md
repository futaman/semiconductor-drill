# モジュールC「つくりかた」メモ

`modules/C.js` の作業メモ。メインのセッションが取り込むための「エンジンへの要望」と「SPEC への反映」をまとめる。

## できたもの

主人公＝スマホのチップの中の1個のトランジスタ。6章、各章に簡易シミュレータを1つ以上（全12個）。

| 章 | 問い（予想クイズ） | シミュレータ | 「ほぅ」→ 次の問い |
|---|---|---|---|
| C1 体になるシリコン | 原料に要る純度は？（9が11個） | `purity` 純度のものさし（わざと混ぜる量と勝手な混じり物を「原子何個に1個」で並べる） | 主人公1個（原子約1000万個）に混じり物が入るのは1万個に1個 → どうやって1つの結晶に？ |
| C2 土台をつくる | ウェーハはなぜ丸い？ | `wafer` 引きの図（結晶 → ウェーハ → 断面。ピンと縮尺バッジ）／`focus` でこぼこと刷り上がりのにじみ | 主人公の体は厚み0.775mmのうち表面の数µmだけ → どう描く？ |
| C3 版で刷る | 1個1秒なら何年？（約6000年） | `expose` 断面ブロックで露光と現像（光の量：少／適量／多）／`shots` ウェーハに版を刷っていく（版にゴミ） | ウェーハ1枚を約20秒で刷る。版のゴミは全チップに写る → 型紙をどう体に？ |
| C4 体をつくる | 部屋は門の前と後どちらに打ち込む？ | `etch` プラズマと液の削り方の比較（溝を埋めて区画）／`build` 工程ボタン8つで主人公を完成させ、門に電圧をかける | 門が傘になり部屋が自動でそろう（セルフアライン）→ 仲間とどうつなぐ？ |
| C5 配線と積み上げ | 配線は何階？（約20階） | `loop` ループのカウンター（1周で1階、20階まで）／`overlay` 上の階の縦穴のずれ | 20階建ての床下の主人公。平均約12週間 → ちゃんと動く？ |
| C6 検査と旅立ち | ゴミ1粒でダメになるのは？ | `dust` ゴミと歩留まり（ウェーハ200/300mm、チップ10/25mm角）／`diff` まちがい探し（引き算）／`zoomout` 主人公 → スマホのズームアウト | 歩留まりがもうけを決める → E（なぜ工場を持てる国は限られる？） |

- 断面ブロックは C3〜C6 で同じ角度・同じ大きさ（`box()`／`drawCols()`）。変わった層は一瞬光る（青緑の縁）。C4 の完成形は C5 の配線タワーと C6 のズームアウトでもそのまま使う。
- 色：電子＝青（部屋の電子の粒、通り道に集まる電子）、レジスト＝紫、版＝グレー、ガラス＝白っぽいグレー、門の材料＝濃いグレー、銅＝黄土色（`--c-cu`、モジュールの CSS で定義。正孔のオレンジとは別の色）。ピンは青緑（`--mark`）。
- 伏線：C1 で A3（`recall` → a3）、C3 で S3（ドームの図）と S4 の版画、C5 で C3 の多色刷りの見当と S4（東京〜大阪の図）、C6 で C2 の丸いウェーハと C3 の版のゴミ。`deeper` は a3・a2・a5・B・D・E。
- 数字の出典はすべて各章の `sources` に書いた（トクヤマ 11N、ASML NXE:3600D の露光範囲・処理能力・重ね合わせ、SIA の工程数とサイクルタイム、TechInsights の配線20層、ISO 14644-1、SEMI M1、Computer History Museum など）。

## 確認したこと

- `http://localhost:8765/#c1`〜`#c6` を通しで解き、全章が完了になる。C モジュール由来のコンソールエラーなし。
- 375px 幅で横スクロールなし。各シミュレータのボタン・スライダーを操作して表示を確認。ライト／ダーク両方。

## エンジンへの要望

1. **`index.html` に `<meta name="viewport" content="width=device-width, initial-scale=1">` がない。** スマホ（とプレビューのモバイル表示）でページが980px幅で描かれ、縮小表示になる。Artifact の公開時に骨組みが付くなら問題ないが、ローカルの確認では効いてしまう（確認時は JS で一時的に足した）。
2. `.fig svg { min-width: 600px; width: 100% }` が sim の中の小さな SVG にも効く。`.frame.sim svg { min-width: 0 }` で min-width は外れるが width:100% は残るので、C では `.c-sim svg.c-ring` のように詳しく指定して上書きした。sim の中の SVG には `.fig svg` を効かせない（例：`.fig .frame:not(.sim) svg`）ほうが、ほかのモジュールも楽。
3. `recall` の `fig` に、ほかのモジュールの図（例：A3 の図）を指定できると、伏線がもっと自然に見せられる（今は `figFn` が自分のモジュールとサマリしか探さない）。C1 では代わりに C の中に小さな図 `pure` を描いた。
4. `deeper` にサマリの章を指定すると「モジュールS」と表示されてしまう。サマリへのリンクを `deeper` で張れるとよい（C3 では S4 へのリンクを `recall` で代用した）。
5. 予想クイズの発見ブロックを開いたとき、`discoverHTML` 内の sim は `mountSims` されるが、`.build` の `observe()` が呼ばれないので、発見のブロックはアニメーションなしで出る（実害はない）。

## SPEC への反映

- 7章（C の方針）に、上の表の6章構成と各章のシミュレータを追記する。KNOWLEDGE 3.1 の案からの変更点：
  - C1 の「ほぅ」は「全人口12回」ではなく「主人公1個（原子約1000万個）に混じり物が入るのは1万個に1個」とした（全人口12回は数字カードの補足に残した）。比べる物差しは「シリコン原子何個に1個」で統一。
  - C1 のたとえ話に「理科室の蒸留」を追加（泥水 ↔ 純度98%のシリコン、沸かす ↔ トリクロロシラン（約32℃で沸く）にする、崩れるところ＝シリコンそのものは3000℃を超えないと沸かない）。
  - C2 の平坦度は「サッカー場にコイン1枚」（Chip Tycoon、未確認）ではなく、ITRS 2006 の見通し（25〜45nm）から「1回に刷る範囲（2.6cm）を100mに拡大すると紙1〜2枚の厚さ」に置き換えた。
  - C3 の予想クイズは「1個1秒なら約6000年」。発見の数字は「ウェーハ1枚を約20秒で刷る」（毎時160枚）。
  - C4 の予想クイズは「部屋は門の前と後どちらに打ち込む？」（セルフアライン）。人物コラムはファジンら（1967〜68年のシリコンゲート）。
  - C5 にたとえ話「街の道路網」（路地・幹線・高速・立体交差）を追加。配線の階数は「約20階」（Lunar Lake の例）。
  - C6 の終わりは「190億分の1」の数字カードと、C 全章の `recap`。
- KNOWLEDGE 4章の数字の状態：
  - 「完成まで約3〜4か月」→ SIA：ウェーハ完成まで平均約12週間（先端14〜20週間）＋組立・検査約6週間。
  - 「工程は1,000ステップ以上」→ SIA：最大約1,400。
  - 「配線は20層以上」→ TechInsights：Lunar Lake（TSMC N3）で20層。
  - 「クリーンルーム1m³に10個以下」→ ISO 14644-1 クラス1（0.1µm以上）。病院・外気との比較は確認できなかったので使っていない。
  - 「インゴット約100kg」「引き上げ速度」は確認できなかったので使っていない。
  - 「サッカー場にコイン1枚」は確認できなかったので上記の計算に置き換えた。

## 気になっていること（未対応）

- 平らな形のトランジスタで説明している（FinFET・GAA はコラムで触れただけ）。
- `build` の工程ボタンは、わざとお手本と違う順に並べている（考えて押してもらうため）。難しすぎるようなら「ヒント」ボタンで次の1手が出る。
- `dust` のゴミは乱数なので、同じ操作でも結果が毎回少し変わる。
